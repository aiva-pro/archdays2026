# 5. Сверка проекта с фактом

Сравниваем проект из репозитория с тем, что найдено на стенде. Какие строки должны получиться, здесь не написано: читаем их на экране.

1. Откройте свою модель в режиме **Объекты**.
2. Откройте **Входящие → Сверка**.

Запускать сверку не нужно, экран показывает текущее состояние. Данные появляются после запуска маппинга на шаге 4. Если список пуст, проверьте, что запуск завершён, и обновите страницу.

Имена объектов после импорта могут начинаться с `[Container] `. На сопоставление это не влияет.

Если на экране нет объектов проекта, проект не сохранён в репозиторий. Вернитесь к [03_model.md](03_model.md).

Режим переключается справа вверху. Слева фильтры со счётчиками. Плитки над списком тоже работают как фильтр.

## От объектов модели

Режим по умолчанию. В списке объекты класса `container`. Фильтры: состояние, слой, класс. В строке видно, сколько записей подтверждают объект, из каких они датасетов и когда объект обнаружен последний раз.

| Состояние | Что это | Что делать |
| --- | --- | --- |
| Подтверждён источником | сервис есть и в проекте, и на стенде | сравнить атрибуты и зависимости |
| Нет в источниках | сервис есть в проекте, на стенде не найден | завести задачу на развёртывание. У `container` есть шаблон «Задача на деплой» |
| Только обнаружен | сервис есть на стенде, в проекте его нет | поправить проект на канвасе: добавить объект и связь, проверить, сохранить |
| Давно не видели | сервис раньше приходил со стенда, теперь не приходит | выяснить, выведен ли он, и решить, оставлять ли его в проекте |

**Записи** в строке открывает второй режим с записями этого объекта. **Открыть** ведёт в карточку объекта в репозитории.

## От записей источников

В списке записи датасетов. Фильтры: статус, маппинг, датасет, класс модели.

| Статус | Что это |
| --- | --- |
| В репозитории | запись связана с объектом модели |
| Ожидает | запись пришла, но с объектом не связана |
| Неактивна | запись больше не действует |

Клик по строке открывает карточку записи. В ней значения со стенда и объект репозитория.

Статуса «дрейф» на экране нет. Чтобы найти расхождения в атрибутах, сравните значения в карточке записи с карточкой объекта проекта.

В карточке есть кнопки **Связать автоматически** и **Создать объект и связать**. Не нажимайте их, пока команда не решила, что делать со строкой.

## Что записать

Одинаковое имя сервиса не гарантирует одинаковые вызовы. Сравните зависимости сервиса на стенде со стрелками на канвасе.

Для каждой строки запишите одно действие. Проект меняйте на канвасе, не на экране сверки.

**Проверка расхождений** в репозитории проверяет только саму модель. Источники она не показывает.

Контрольная точка: оба режима просмотрены, для каждой строки записано действие.
