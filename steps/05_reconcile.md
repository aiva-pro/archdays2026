# 5. Сверка проекта с фактом

Сравниваем проект (то, что сохранили в репозиторий) с фактом стенда. Строки своей модели читаете вы. Ожидаемый состав строк здесь не приводится.

1. Откройте свою модель в режиме **Объекты**.
2. **Входящие → Сверка**.

Отдельной кнопки запуска нет: экран показывает текущее состояние. Привязка к классу `container` появляется в течение нескольких минут после сбора. Если строк нет, подождите следующий прогон и обновите страницу. Имена после импорта могут начинаться с `[Container] `: привязка это учитывает.

Пока проект не сохранён в репозиторий, сверять не с чем: объектов проекта на экране нет. Вернитесь к [03_model.md](03_model.md).

У сверки два режима, переключатель справа вверху. Слева фильтры со счётчиками, над списком плитки сводки: клик по плитке включает фильтр.

## От объектов модели

Открывается по умолчанию. В списке объекты классов, которые приходят из интеграции, у нас это `container`. Фильтры: состояние, слой, класс. В строке видно, сколько записей и из каких датасетов подтверждают объект и когда он последний раз обнаружен.

| Состояние | Что это | Что делать |
| --- | --- | --- |
| Подтверждён источником | сервис есть и в проекте, и на стенде | сверить атрибуты и зависимости |
| Нет в источниках | есть в проекте, на стенде не найден | задача довести развёртывание; у `container` есть шаблон «Задача на деплой» |
| Только обнаружен | есть на стенде, в проект не принят | правка проекта через канвас: объект, связь, проверить, сохранить |
| Давно не видели | раньше приходил со стенда, теперь нет | выяснить, выведен ли сервис, и решить, что с ним в проекте |

Кнопка **Записи** в строке открывает второй режим по этому объекту, **Открыть** — карточку объекта в репозитории.

## От записей источников

Тот же факт со стороны стенда: записи датасетов и что с ними стало в модели. Фильтры: статус, маппинг, датасет, класс модели.

| Статус | Что это |
| --- | --- |
| В репозитории | запись связана с объектом модели |
| Ожидает | запись пришла, с объектом ещё не связана |
| Неактивна | запись больше не действует |

Клик по строке открывает карточку записи: значения, которые прислал стенд, и объект репозитория. Отдельного статуса «дрейф» нет: расхождение атрибутов читайте здесь, сравнивая значения записи с карточкой объекта проекта.

В карточке есть кнопки сопоставления (**Связать автоматически**, **Создать объект и связать**). Не нажимайте их, пока команда не решила, что делать со строкой.

## Что записать

Совпадение имени не означает совпадение вызовов. Зависимости сервиса на стенде сравните со стрелками на канвасе.

По каждой своей строке запишите одно действие. Изменения проекта делайте на канвасе, не на экране сверки.

Экран **Проверка расхождений** в репозитории теперь проверяет только саму модель; соответствие с источниками смотрите на **Сверке**.

Контрольная точка: сверка прочитана в обоих режимах, по строкам есть решение.
