# 5. Сверка проекта с фактом

Сравниваем проект (то, что сохранили в репозиторий) с фактом стенда. Строки своей модели читаете вы. Ожидаемый состав строк здесь не приводится.

1. **Интеграции → Сверка**.
2. Выберите свою модель.
3. Нажмите **Запустить сверку**.

Привязка к классу `container` появляется в течение нескольких минут. Если её нет, нажмите **Обновить списки** и дождитесь следующего прогона. Имена после импорта могут начинаться с `[Container] `: привязка это учитывает.

Пока проект не сохранён в репозиторий, сверка видит пустой проект и строки выглядят как «нет в модели». Вернитесь к [03_model.md](03_model.md).

Рядом есть экран **Репозиторий → Расхождения → Интеграция**: после сопоставления там можно нажать **Перепроверить**. Состав строк читайте на **Интеграции → Сверка**.

| Статус | Что это | Что делать |
| --- | --- | --- |
| Совпадает | сервис есть и в проекте, и на стенде | сверить атрибуты и зависимости |
| Нет в источнике | есть в проекте, на стенде не найден | задача довести развёртывание; у `container` есть шаблон «Задача на деплой» |
| Нет в модели | есть на стенде, в проекте объекта нет | правка проекта через канвас: объект, связь, проверить, сохранить |
| Дрейф | объект есть с обеих сторон, разошлись атрибуты или зависимости | команда выбирает, какая сторона задаёт значение |

Совпадение имени не означает совпадение вызовов. Колонку зависимостей на стенде сравните со стрелками на канвасе.

По каждой своей строке запишите одно действие. Изменения проекта делайте на канвасе, не на экране сверки.

Контрольная точка: сверка запущена, по строкам есть решение.
