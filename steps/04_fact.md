# 4. Загрузка факта

Порядок: подключение → payload → датасет → маппинг на модель → репозиторий.

Сначала сохраните проект в репозиторий ([03_model.md](03_model.md)). Без него факт не с чем сопоставлять.

Кнопку **Опубликовать всё готовое** не нажимайте: она принимает найденное в проект.

Шаги 1–3 выполняются на уровне организации. В боковой панели переключите режим работы на **Конфиг** и откройте **Интеграции**. Вверху раздела три вкладки: **Подключения**, **Payloads**, **Датасеты**.

## 1. Подключение

Подключение `ECOM_DOCKER` в организации уже есть, создавать его не нужно. Оно работает через коллектор на машине магазина: коллектор читает Docker и каждые две минуты присылает данные в AIVA.

1. Откройте **Интеграции → Подключения** и подключение `ECOM_DOCKER`.
2. Проверьте, что статус рабочий и последний запуск был недавно.

На контейнерах стенда уже стоят метки: `aiva.system` (система команды с карточки), `aiva.service`, `aiva.c4`, `aiva.kind`, `aiva.tech`, `aiva.owner`, `aiva.version`, `aiva.port`, `aiva.depends_on`.

Контрольная точка: подключение работает.

## 2. Payload и сбор

Payload задаёт, что забирать из подключения. Здесь это контейнеры.

1. Откройте **Интеграции → Payloads** и payload `containers` подключения `ECOM_DOCKER`.
2. Откройте вкладки **Запуски** и **Лог**. Сбор идёт сам каждые две минуты, в логе должны быть записи.
3. Найдите записи с меткой `aiva.system` своей команды. Остальные не трогайте.
4. Сравните список с https://ecomarch.aiva-pro.tech/status.

Контрольная точка: в логе есть записи системы команды.

## 3. Датасет

Датасет превращает сырую запись Docker в запись с полями. Он пришёл вместе с метамоделью.

1. Откройте **Интеграции → Датасеты** и датасет «ArchDays: Docker → сервисы магазина».
2. На вкладке **Маппинг** посмотрите, из какой метки берётся каждое поле. Рядом показан результат на образце записи.

| Метка | Поле датасета |
| --- | --- |
| `aiva.service` | имя |
| `aiva.tech` | технология |
| `aiva.owner` | команда |
| `aiva.version` | версия |
| `aiva.port` | порт |
| `aiva.description` | описание |
| `aiva.kind` | тип (`API` или веб-приложение) |

3. Если записей в датасете нет, откройте вкладку **Обработка** и нажмите **Обработать сейчас**.

Если датасета нет или у него статус «Без маппера», позовите ведущего.

Контрольная точка: в датасете есть записи контейнеров.

## 4. Маппинг на модель

Этот шаг выполняем в модели команды. Переключите режим работы на **Объекты**. В боковой панели появится блок **Входящие**.

1. Откройте **Входящие → Маппинги**.
2. Откройте маппинг класса `container`.
3. На вкладке **Маппинг** посмотрите, какие поля датасета становятся атрибутами класса.
4. Откройте вкладку **Запуски**. Выберите юнит своей команды и нажмите **Привязать всё непривязанное**.
5. Дождитесь окончания запуска. В его итоге видно, сколько записей связано с объектами проекта и сколько только обнаружено.

Сам маппинг объекты не создаёт: автозапуск у него выключен, поэтому запускаем вручную.

Запуск не меняет проект. Сервисы, совпавшие по имени, связываются с объектами проекта. Остальные остаются обнаруженными. Значения со стенда записываются на обнаруженные объекты, карточки объектов проекта не меняются.

Контрольная точка: запуск завершён без ошибок.

## 5. Репозиторий

Откройте **Содержимое модели** и проверьте:

- объекты проекта на месте;
- появились обнаруженные объекты со стенда;
- атрибуты объектов проекта не изменились.

Нет проекта — вернитесь к [03_model.md](03_model.md) и сохраните канвас. Нет обнаруженных объектов — пройдите шаги 1–4 ещё раз или позовите ведущего.

Контрольная точка: в репозитории есть и проект, и обнаруженные объекты.

Дальше: [05_reconcile.md](05_reconcile.md).
