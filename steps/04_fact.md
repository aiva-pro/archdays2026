# 4. Загрузка факта

Один проход: подключение → payload → датасет → маппинг на модель → репозиторий.

Предусловие: проект сохранён в репозиторий ([03_model.md](03_model.md)). Иначе сопоставлять факт будет не с чем.

До чтения сверки не нажимайте **Привязать всё непривязанное** и **Опубликовать всё готовое**.

Первые три шага — на уровне **организации**: в боковой панели переключите режим работы на **Конфиг** и откройте **Интеграции**. Вверху раздела три вкладки по пути данных: **Подключения**, **Payloads**, **Датасеты**.

## 1. Подключение

Подключение читает Docker API стенда, порт `50006`, только чтение, авторизация не нужна.

1. **Интеграции → Подключения**.
2. На подготовленном стенде подключение Docker уже может быть: откройте его и проверьте поля. Если его нет, нажмите **Добавить подключение**.

| Поле | Значение |
| --- | --- |
| Тип | Docker |
| Код | `ECOM_DOCKER` (именно так: к этому коду привязан датасет, который пришёл с метамоделью) |
| Где исполняется | **Облако AIVA**, если стенд доступен по URL; иначе Edge-коллектор, как скажет ведущий |
| Docker API URL | `http://<хост>:50006` с карточки |
| Unix socket | пусто |

3. Дождитесь проверки: «Подключение работает».

Метки на контейнерах стенда уже стоят: `aiva.system` (ваша система с карточки), `aiva.service`, `aiva.c4`, `aiva.kind`, `aiva.tech`, `aiva.owner`, `aiva.version`, `aiva.port`, `aiva.depends_on`.

Контрольная точка: проверка подключения успешна.

## 2. Payload и сбор

Payload — что именно забираем из подключения. Нам нужны контейнеры.

1. **Интеграции → Payloads**. Если payload `containers` у подключения `ECOM_DOCKER` уже есть, откройте его. Если нет: **Добавить payload** → подключение `ECOM_DOCKER` → сущность `containers`.
2. Запустите сбор: в подключении нажмите **Запустить сейчас**.
3. Откройте вкладки **Запуски** и **Лог**: запуск завершился, записи пришли.
4. В записях — контейнеры с меткой `aiva.system` вашей команды. Чужие и служебные записи без этой метки не разбираем.
5. Сверьте список с https://ecomarch.aiva-pro.tech/status.

Контрольная точка: записи со стенда приходят, ответ не пустой и не сплошные ошибки.

## 3. Датасет

Сырая запись Docker ещё не объект модели. Датасет превращает payload в записи с полями. На стенде он выдан вместе с метамоделью: **Интеграции → Датасеты** → «ArchDays: Docker → сервисы магазина». Откройте и **прочитайте** вкладку **Маппинг**: слева поле датасета, рядом выражение и результат на образце записи. С нуля собирайте, только если ведущий сказал, что датасета нет.

| Метка | Поле датасета |
| --- | --- |
| `aiva.service` | имя |
| `aiva.tech` | технология |
| `aiva.owner` | команда |
| `aiva.version` | версия |
| `aiva.port` | порт |
| `aiva.description` | описание |
| `aiva.kind` | тип (`API` или веб-приложение) |

Если записей в датасете нет, откройте вкладку **Обработка** и нажмите **Обработать сейчас**.

Контрольная точка: в датасете есть записи контейнеров.

## 4. Маппинг на модель

Дальше работаем **внутри своей модели**: переключите режим работы на **Объекты**, в боковой панели появится блок **Входящие**.

Сохранение проекта запускает сопоставление с уже собранным фактом, отдельный ручной прогон не нужен.

1. Откройте **Входящие → Маппинги**.
2. У класса `container` виден датасет сервисов магазина. Откройте маппинг.
3. Вкладка **Маппинг**: какие поля датасета становятся атрибутами класса. Вкладка **Запуски**: когда записи превращались в объекты и с каким итогом (связано, только обнаружено, ошибки).
4. Совпавшие сервисы связаны с объектами проекта. Фактические значения лежат на обнаруженных объектах. Значения проекта на своих карточках не перезаписываются.

Совпадение по имени ещё не значит совпадение связей и атрибутов: это вы увидите на сверке. Пока только наблюдайте, не принимайте найденное в проект оптом.

Если при сохранении канваса вышло предупреждение о сверке, проект уже записан. Повторно не публикуйте, позовите ведущего.

## 5. Репозиторий

Откройте **Содержимое модели** и убедитесь, что:

- объекты **проекта** на месте (то, что вы сохранили);
- рядом виден **факт** (обнаруженные и сопоставленные записи), и проект ими не переписан.

Если проекта нет, вернитесь к [03_model.md](03_model.md) и сохраните канвас. Если факта нет, вернитесь к шагам 1–4 или позовите ведущего.

Контрольная точка: в репозитории есть и проект, и след загруженного факта.

Дальше: [05_reconcile.md](05_reconcile.md).
