# 4. Проект на канвасе

0:30–1:00. Файл схемы: `c4/target/workspace.dsl`. В интерфейс нужен этот DSL, не JSON.

## Канвас

1. **Изменения → Создать канвас**. Название, например «ArchDays Store — целевая».
2. Назначьте юнит. Без него сохранение в репозиторий не пройдёт (`canvas.missing.unit`).

## Импорт

1. Табличный режим → **Импорт из Structurizr**.
2. Выберите `c4/target/workspace.dsl`.
3. Включите **Создать вкладки из Views**.
4. **Импортировать**.

На канвасе появятся покупатель, система магазина, контейнеры и платёжный провайдер.

## Класс внешней системы

В Structurizr нет отдельного типа внешней системы, поэтому провайдер описан как `softwareSystem` с тегом `externalSystem`. Импорт по этому тегу сам присваивает класс **External System**.

1. Найдите **Платёжный провайдер**.
2. Проверьте его класс: должен быть **External System**.
3. Если стоит **Software System**, смените класс на `externalSystem` вручную.

## Проверка и сохранение

1. Режим рисования → **Проверить**. Закройте ошибки на вкладках «Элементы» и «Связи».
2. Если в статусной панели канваса есть **Предложить**, зафиксируйте предложение, когда правки больше не нужны.
3. **Сохранить** в репозиторий. Черновик сверка не читает.
4. Проставьте ключевым объектам статус **Согласовано**.

Разберите схему по стрелкам: кто кого вызывает и какие контейнеры входят в систему. Это проект. Он не подменяется списком со страницы `/status`.

| Проблема | Что сделать |
| --- | --- |
| Нет класса у элемента | метамодель импортирована из `aiva/metamodel.import.json` |
| Лишняя иерархия или вторая связь там, где допустима одна | оставьте одну связь |
| Канвас ещё не собран, зал ушёл дальше | скажите ведущему: он выдаст модель `WS_STEP2`, продолжайте с проверки |

Контрольная точка: объекты в репозитории, статус Согласовано.
