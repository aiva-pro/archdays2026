# Словарь терминов AIVA

Термины ниже — в смысле платформы AIVA. Если на экране подпись чуть другая, ориентируйтесь на смысл.

## Основа

| Термин | Что это в AIVA |
| --- | --- |
| **AIVA** | Платформа архитектурного моделирования: метамодель, модель, изменения, интеграции и сверка с реальностью. |
| **Организация** | Рабочее пространство команды. |
| **Модель** | Пространство одной архитектур |

## Метамодель и язык

| Термин | Что это в AIVA |
| --- | --- |
| **Метамодель** | Язык модели: какие классы объектов бывают, какие у них атрибуты, какие связи допустимы, какие статусы есть у решения. Редактируется в **Конструкторе**. |
| **Конструктор** | Раздел модели для настройки метамодели (вкладки **Общее**, **Структура**, **Связи**, **Статусы** и др.). |
| **Слой** | Группа классов в метамодели (на воркшопе — слой **C4 Architecture**). |
| **Класс** | Тип объекта архитектуры (`person`, `softwareSystem`, `externalSystem`, `container`, `component` и т.д.). У класса — атрибуты, допустимые связи, флаги поведения. |
| **Атрибут** | Свойство объекта или класса (технология, команда, порт, версия…). |
| **Отношение** | Правило связи между классами в метамодели (кто с кем может быть связан и как). |
| **Статус** / **статусная модель** | Жизненный цикл объекта решения (Черновик → … → Согласовано → …). |
| **Импорт метамодели** | Загрузка языка в модель из JSON (**Импорт из JSON** на вкладке **Общее**). Обычно в пустую модель. |

## Проект и содержимое

| Термин | Что это в AIVA |
| --- | --- |
| **Проект** | Утверждённое описание целевой архитектуры в модели: объекты, атрибуты, связи, статусы. На воркшопе приходит из Structurizr и сохраняется в репозиторий. |
| **Объект** | Объект, экземпляр класса в модели (конкретный `catalog`, покупатель, система…). |
| **Связь** | Связь между объектами (кто кого вызывает / использует). |
| **Репозиторий** | Сохранённое содержимое модели. |
| **Содержимое модели** | Раздел, где можно просмотреть объекты репозитория и их связи. |
| **Граф** | Представление связей репозитория: кто от кого зависит. |
| **Изменение** | Черновик правок архитектуры (канвас). В репозиторий попадает только при сохранении канваса. ЖЦ "Актвный-Предложен-Опубликован" |
| **Вкладка** | Отдельный viewpoint изменения. |
| **Предложить** | Зафиксировать изменение к сохранению (статус «Предложен»), когда правки больше не нужны. Блокируется на внесение изменений. |
| **Сохранить** (в репозиторий) | Перенести содержимое изменения в репозиторий модели. После проект становится частью репозитория. |
| **Проверить** | Валидация проекта на соответствие правилам метамодели и текущему содержимому репозитория. |

## Факт и интеграции

| Термин | Что это в AIVA |
| --- | --- |
| **Факт** | То, что реально обнаружено во внешней системе (на воркшопе — стенд магазина), а не нарисовано в проекте. |
| **Подключение** | Настройка на уровне организации: откуда AIVA читает внешний мир (стенд, API, коннектор). |
| **Источник** / **коннектор** | Внешняя система и тип подключения к ней (например Docker API стенда). В интерфейсе это раздел **Подключения**. |
| **Payload** | Что именно забираем из подключения (у Docker — `containers`) и сырой ответ «как пришёл»: ещё не объекты модели, а первичные данные приёма. |
| **Трансформация** | Преобразование payload в нормализованный **датасет**. |
| **Датасет** | Нормализованный набор записей факта после трансформации (список сервисов/контейнеров и их полей), ещё до записи в язык модели. |
| **Маппинг** | Правила, как поля датасета кладутся на классы и атрибуты метамодели (например запись стенда → класс `container`). |
| **Входящий маппинг** | Маппинг внутри модели (**Входящие → Маппинги**): его запуск превращает записи датасета в обнаруженные объекты на языке модели. |
| **Загрузка** | Результат прогона: что из факта уже видно в модели как обнаруженное. |
| **Матчинг** / **сопоставление** | Связка обнаруженного факта с объектами проекта в репозитории (по ключу/имени и правилам). Проект при этом сам не переписывается. |
| **Сверка** | Экран сравнения проекта и факта (**Входящие → Сверка**) в двух режимах. От объектов модели: подтверждён источником, нет в источниках, только обнаружен, давно не видели. От записей источников: в репозитории, ожидает, неактивна. |
| **Дрейф** | Объект есть и в проекте, и в факте, но разошлись атрибуты или зависимости. Отдельного статуса на сверке нет: читается в карточке записи. |
| **Привязать всё / Опубликовать всё готовое** | Действия, которые принимают найденный факт в проект. До чтения сверки на воркшопе их не нажимают. |
